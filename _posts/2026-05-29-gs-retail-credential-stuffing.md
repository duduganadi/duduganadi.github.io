## 개요

GS리테일은 2024년 12월 27일부터 2025년 1월 4일 사이 GS25 홈페이지 해킹으로
고객 9만여 명의 개인정보가 유출됐다고 밝혔다. 해킹 수법은 **크리덴셜 스터핑**이었다.

이후 추가 조사에서 GS샵 홈쇼핑 사이트에서도 158만 명 이상이 추가로 피해를 입은 것으로 드러났다.
조사 대상 기간은 2024년 6월 21일부터 2025년 2월 13일까지였고,
추가 조사에 따라 피해자는 더 늘어날 수도 있다고 하였다.

---

## 크리덴셜 스터핑이란?

크리덴셜 스터핑은 "비밀번호를 직접 뚫는" 공격이 아니다.
이미 다른 곳에서 유출된 계정 목록을 가져다가 자동으로 대입하는 방식이다.

---

## 공격 흐름

| 단계 | 내용 | 구분 |
|---|---|---|
| 1 | 콤보리스트 입수 (다크웹에서 ID/PW 쌍 수백만 건 구매) | 준비 |
| 2 | 자동화 봇 툴 설정 (OpenBullet / Sentry MBA) | 준비 |
| 3 | 프록시 로테이션 (수천 개 IP로 요청 분산 → IP 차단 우회) | 탐지 우회 |
| 4 | 대량 자동 로그인 시도 (초당 수천 건, 정상 트래픽처럼 위장) | 공격 실행 |
| 5 | 성공 계정 수집 (개인정보 열람, 저장) | 수확 |
| 6 | 2차 피해 발생 (스미싱, 포인트 탈취, 다크웹 재판매) | 현금화 |

## 핵심 해킹 원리
브루트포스 VS 크리텐셜 스터핑
| 구분 | 브루트포스 | 크리덴셜 스터핑 |
|:----:|:----:|:----:|
| 비밀번호 | 무작위 생성해서 대입 | 이미 유출된 실제 비밀번호 사용 |
| 성공률 | 매우 낮음 | **0.1~2% (훨씬 높음)** |
| 탐지 | 같은 계정에 반복 실패 → 쉽게 탐지 | 계정마다 한두 번 시도 → 탐지 어려움 |
| 전제조건 | 없음 | 다른 곳의 유출 데이터 필요 |
크리덴셜 스터핑이 가능한 근본 이유는 비밀번호 재사용 습관이다. 
한 설문 조사에 따르면 사용자의 81%가 두 개 이상의 사이트에서 같은 비밀번호를 재사용했다고 뜬다. 
공격자가 노리는 것이 바로 이 부분이다.

## 봇 툴의 실제 작동 방식

**정상 사용자 로그인**
- IP : 집 고정
- User-Agent : Chrome/120.0
- 로그인 실패 → 재시도 간격 수 분
- 쿠키·세션 정상 보유

**봇 (위장 완료)**
- IP : 매 요청마다 교체
- User-Agent : 실제 브라우저 흉내
- 계정마다 1회만 시도
- JS 실행·쿠키 정상 처리

---

## 봇의 탐지 우회 기법

- **프록시 로테이션** : 요청마다 다른 IP 사용. 주거용 IP 대역 사용 시 탐지 거의 불가
- **User-Agent 위장** : 실제 Chrome/Safari 헤더 복제
- **속도 조절** : 계정당 1~2회만 시도해 Rate limit 우회
- **캡차 우회** : AI 캡차 솔버 또는 외주 인력 활용

---

## GS리테일이 8개월간 못 막은 이유

- **MFA 미적용** : 아이디/비밀번호만으로 로그인 가능. 2차 인증 없으면 크리덴셜만으로 뚫림
- **봇 탐지 부재** : 비정상 로그인 패턴 미탐지. 실시간 이상 트래픽 모니터링 없음
- **로그 분석 지연** : GS샵 피해는 8개월 후에야 발견. 실시간 이상 탐지 시스템 전무

## 대응 방식
| 문제 | 내용 |
|:----:|:----:|
| MFA(다중 인증) 미적용 | 비밀번호 하나만 맞으면 바로 로그인 가능 — 크리덴셜 스터핑의 가장 쉬운 먹잇감 |
| 실시간 봇 탐지 부재 | 비정상적인 대량 로그인 시도를 수개월간 감지 못함 |
| 늦은 피해 인지 | GS샵 피해는 2024년 6월부터 시작됐는데 2025년 2월에야 발견됐어. 8개월간 방치 |
| 계정 이상 탐지 없음 | 동일 계정에 다른 IP·기기에서 로그인해도 경보 없음 |
| 반복 사고 | GS리테일은 2021년에도 개인정보 유출 사고가 있었으나, 그 이후에도 보안 투자가 충분히 이뤄지지 않음 |
